## v0.1.3 — 2026-09-29

**Additive product release** — 0.1.3 is a patch-level product increment that adds
one new readiness primitive to the C ABI and its C++ façade. The C ABI version,
wire protocol, ExternalObject adapter, and ExtendScript wrapper are unchanged;
no existing entry point, struct layout, or wire byte is affected.

### Added

- `vipc_channel_wait_readable()` / `vectoripc::Channel::wait_readable()`: a
  bounded, non-consuming readiness wait for persistent channels. A long-lived
  helper can wait for peer activity without starting a framed read, so an idle
  poll avoids the partially consumed frame that a receive-based poll would
  poison.
- **Readiness failure contract.** The API is new in v0.1.3, so this is its
  initial contract rather than a change to any released behavior. A readiness
  timeout is non-destructive: `VIPC_ERR_TIMEOUT` consumes no bytes and leaves
  the channel open and synchronized. `VIPC_ERR_BUSY` is returned immediately and
  never blocks. A definitive terminal failure — `VIPC_ERR_PEER_CLOSED` or a real
  I/O failure — closes the channel before returning, so
  `vipc_channel_is_open()` reports the truth and later operations report
  `VIPC_ERR_NOT_CONNECTED`.
- `VIPC_PHASE_WAIT_READABLE` (`11`) and its `"wait-readable"` phase name.
- `vectoripc_readiness_stress`: repeated idle readiness timeouts followed by a
  verified duplex exchange, peer-close detection (clean teardown and abrupt
  process exit), single-reader-slot `VIPC_ERR_BUSY` collisions, and long-idle
  duplex survival. Registered in the Release, `/analyze`, and AddressSanitizer
  gates; a longer configuration also runs in `npm run test:stress`.
- `vectoripc_readiness_idle_bench` (`npm run bench:idle`): idle CPU measured with
  `GetThreadTimes`/`GetProcessTimes` against wall time, reporting sample count,
  min/median/p95/max, a counter liveness check, tick-quantum detection, a
  matched-duration blocked control, and a CPU budget gate.

### Changed

- **Receive timeout semantics are unchanged and restated.** A
  `vipc_channel_receive()` timeout keeps its existing hard-deadline poison
  semantics, because a partial framed read may already have consumed bytes. That
  destructive rule is what distinguishes it from the non-destructive readiness
  timeout introduced above.
- `VIPC_READABLE_POLL_MS` (2 ms) is documented as a nominal poll period rather
  than a latency promise: `Sleep()` rounds up to the 15.625 ms system timer tick,
  so readiness is tick-bounded. See decision D23 and `docs/BENCHMARKS.md`.

| Surface | v0.1.3 |
|---|---|
| Product version | `0.1.3` |
| C ABI | `1` — unchanged (additive entry point only) |
| Wire protocol | `VIPC/1.0` — unchanged |
| ExternalObject adapter | `3` — unchanged |
| ExtendScript wrapper | `5` — unchanged |
| ESABI dependency | `v0.3.0` / `3e99040c43cef573b477ad372b2a3a96c4d3a7d7` |

No wire bytes, operation IDs, payload limits, endpoint semantics, session-handle
format, wrapper commands, struct layouts, or existing transport APIs changed.
Because `vipc_channel_wait_readable()` closes the channel on a terminal failure,
a consumer must check `vipc_channel_is_open()` after any non-timeout,
non-`VIPC_ERR_BUSY` readiness return rather than assuming the channel survived.

### Measured

Idle readiness cost, `npm run bench:idle -- 60000 5 200 60`, 300 s of continuous
waiting against a silent peer on the same machine:

| Measurement | Value |
|---|---|
| Waiter thread CPU, aggregate | **0.104 % of one core** |
| Conservative upper bound | **0.130 % of one core** |
| Matched 300 s blocked control | **0.000 ms** process CPU |
| Readiness wake latency, median / p95 | **8.116 ms / 14.972 ms** |
| Readiness wake latency, max | 15.833 ms |
| Deadline accuracy, worst deviation on 60,000 ms | 11.302 ms (one timer tick) |

Idle CPU is effectively zero and wake latency sits on the system timer tick,
which is below the host's own event cadence for the Workmark helper boundary.
The `PeekNamedPipe()` poll design is retained for v0.1.3; no overlapped or
event-driven readiness was introduced. Decisions: `docs/DECISIONS.md` D23.

### Validation

Full `npm run verify` on the release candidate:

- Release/native suite, MSVC `/W4 /WX /sdl`: 12/12 CTest targets passed.
- `vectoripc_readiness_stress` passed in the Release, `/analyze`, AddressSanitizer,
  and stress gates; the stress gate runs 200 idle rounds followed by a
  20 × 5,000 ms (100 s) long-idle window.
- Installed package: independent C11 and C++17 consumers passed. They prove
  `wait_readable` is exported by the installed headers and static library, and
  both exercise the detached/invalid-argument seam — a null (C) or detached (C++)
  channel returns `VIPC_ERR_INVALID_ARGUMENT` with
  `error.phase == VIPC_PHASE_WAIT_READABLE`.
- Façade idle-timeout and ready-path coverage lives in `tests/cpp_api.cpp`
  (`vectoripc_cpp_api`), not in the installed-package consumers: the C++ API
  target asserts the non-destructive idle `VIPC_ERR_TIMEOUT` result and the
  ready `VIPC_OK` results on both the server and client side of a live channel.
- MSVC static analysis: pass.
- MSVC AddressSanitizer: 12/12 targets passed.
- Unchanged transport gates: 19 payload sizes through 16 MiB; 2,000 timeout
  cycles and 2,000 accepts + 500 blocked writes with process handles 69 → 69;
  100,000 messages each direction; 1,000,000 verified frames at 247.1 MiB/s;
  50,000 verified 256 KiB frames at 1,713.1 MiB/s.

The handle baseline is 69 rather than the 60 recorded for v0.1.2; it is a
per-run process baseline, and the invariant that matters — before equals after
across thousands of cancellation cycles — holds.
